# Notice Board

An internal notice board for a bank branch network. React frontend, FastAPI backend on
AWS Lambda, MongoDB Atlas for storage, served over HTTPS through CloudFront.

Anyone can read the board without signing in. Posting, editing and archiving require a
staff login backed by JWT.

> Built for the Full-Stack AWS workshop. See [ASSIGNMENT.md](./ASSIGNMENT.md) for the
> tier requirements and [STAGES.md](./STAGES.md) for the build order this project follows.

## Architecture

```
                    Browser
                       │
        ┌──────────────┴───────────────┐
        │                              │
   page load                      API calls
        │                              │
        ▼                              ▼
   CloudFront  ──(OAC, SigV4)──▶  API Gateway (HTTP API)
        │                              │
        ▼                              ▼
   S3 (private)                  Lambda (python3.13)
   React bundle                  FastAPI via Mangum
                                       │
                                       ▼
                                 MongoDB Atlas
```

**Why these pieces.** S3 is private and reachable only through CloudFront's Origin
Access Control, so there is exactly one public entry point and it is HTTPS. API Gateway
proxies every path to a single Lambda (`ANY /{proxy+}`), so FastAPI owns routing rather
than duplicating it in Terraform. Mangum adapts the API Gateway event to ASGI, which
means the same `app` object runs under uvicorn locally and Lambda in AWS — there is no
"works locally, breaks deployed" divergence.

### Backend layering

The backend is a layered (hexagonal) application. Dependencies point **inward**, toward
the domain:

```
api/  ──▶  services/  ──▶  repositories/base.py (ports)  ──▶  domain/
                                     ▲
                    memory.py ───────┴─────── mongo.py   (adapters)
```

| Layer | Responsibility | May not know about |
|-------|----------------|--------------------|
| `api/` | Parse request, call a service, shape JSON | Mongo, bcrypt |
| `services/` | Business rules | HTTP status codes, BSON |
| `domain/` | Entities and their behaviour — pure stdlib | Any framework |
| `repositories/` | `base.py` declares the ports; `memory.py` and `mongo.py` implement them | — |
| `schemas/` | Pydantic DTOs — the wire contract | Storage details |
| `security/` | bcrypt hashing, JWT mint/verify, auth dependencies | Business rules |

The payoff is concrete: switching storage from an in-memory dict to MongoDB was a change
to `dependencies.py` plus a new `mongo.py`. No route, no service and no test changed.
The in-memory adapter is still used as the test double.

Each package's `__init__.py` documents that layer's contract in more detail.

## Local setup

**Prerequisites:** Python 3.12+, Node 18+, a MongoDB Atlas connection string.
(Local development uses Python 3.14; Lambda runs 3.13.)

### 1. Backend

```bash
cd 02-notice-board
python -m venv .venv
.venv\Scripts\activate            # PowerShell:  .venv\Scripts\Activate.ps1
                                  # macOS/Linux: source .venv/bin/activate
pip install -r backend/requirements.txt -r backend/requirements-dev.txt
```

Create `.env` in the project root (gitignored — never commit it):

```ini
MONGODB_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/noticeboard
MONGODB_DB=noticeboard
JWT_SECRET=<a long random string>
JWT_EXPIRATION_MINUTES=60
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://localhost:4173
REPOSITORY=mongo
```

Run it:

```bash
cd backend
python -m uvicorn app.main:app --reload --port 8000
```

- API: <http://localhost:8000/api/notices>
- Interactive docs: <http://localhost:8000/docs>

On first start the app seeds four demo employees and three notices, but only if the
collections are empty — the seed counts before writing, so restarts never duplicate.

### 2. Frontend

```bash
cd frontend
npm install
npm run dev          # http://localhost:5173
```

`VITE_API_URL` defaults to `http://localhost:8000`. To point at a deployed API:

```powershell
$env:VITE_API_URL = "https://<id>.execute-api.us-east-1.amazonaws.com"
npm run build
```

Vite **bakes this value into the bundle at build time** — changing the API URL means
rebuilding, not just re-uploading.

### `REPOSITORY=memory`

Set `REPOSITORY=memory` to run the whole app against an in-process dict with no database
at all. Useful for demos and offline work; data disappears on restart.

## API reference

Base path `/api`. Reads are public; writes require `Authorization: Bearer <token>`.

### Notices

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/notices` | — | The live board. Supports `?category=` and `?department=`. Excludes archived and expired notices; ordered pinned first, then priority, then newest. |
| `GET` | `/api/notices/{id}` | — | One notice. `404` if the id does not resolve. |
| `POST` | `/api/notices` | ✅ | Create. Returns `201` with a `Location` header. |
| `PUT` | `/api/notices/{id}` | ✅ | Update. Omitted fields are left unchanged. |
| `DELETE` | `/api/notices/{id}` | ✅ | **Archives** (soft delete) — returns `204` and the notice leaves the board. |

### Auth

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `POST` | `/api/auth/login` | — | Returns a JWT plus the profile fields the UI needs. |
| `POST` | `/api/auth/register` | ADMIN | Provision a staff account. Admin only — staff accounts are issued, not self-served. |
| `GET` | `/api/auth/me` | ✅ | Who the server thinks you are. The fastest way to debug an auth problem. |

### Health

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/health` | — | `{"status":"UP","repository":"mongo","time":...}` — the `repository` field tells you which storage backend is live. |

### Request and response shapes

`POST /api/notices`

```json
{
  "title": "Wire transfer cutoff moves to 16:00 ET",
  "body": "Same-day wire requests must be submitted by 16:00 ET from Monday.",
  "category": "OPERATIONS",
  "priority": "HIGH",
  "department": "RETAIL_BANKING",
  "expires_at": null
}
```

There is **no author field**, deliberately. The author comes from the JWT, so it cannot
be forged from the request body.

- `category` — `COMPLIANCE`, `SECURITY_ALERT`, `OPERATIONS`, `IT_SYSTEMS`, `HR`, `GENERAL`
- `priority` — `LOW`, `NORMAL`, `HIGH`, `URGENT`
- `department` — free text; `null` means bank-wide (visible to everyone)

**Business rule:** a `COMPLIANCE` or `SECURITY_ALERT` notice posted at `LOW` priority is
automatically escalated to `HIGH`. Categories that require acknowledgement are never low
priority, whatever the author selected.

Every error — including `401` and `403` — comes back in one shape, so the frontend needs
a single error handler:

```json
{
  "timestamp": "2026-08-17T01:47:39.063187Z",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "path": "/api/notices",
  "field_errors": { "title": "must not be blank" }
}
```

## Deployment

### Prerequisites

- AWS CLI configured (`aws configure`)
- Terraform installed
- `terraform/terraform.tfvars` populated (gitignored):

```hcl
student_name = "santosh-nukala"
mongodb_uri  = "mongodb+srv://..."
mongodb_db   = "noticeboard"
jwt_secret   = "..."
```

### Manual deploy

```bash
# 1. Package the Lambda
python build.py                # -> backend/lambda.zip (~9.5 MB)

# 2. Provision
cd terraform
terraform init
terraform plan
terraform apply                # CloudFront takes 5-10 minutes

# 3. Build and upload the frontend
cd ../frontend
$env:VITE_API_URL = "$(terraform -chdir=../terraform output -raw api_url)"
npm run build
aws s3 sync dist/ s3://$(terraform -chdir=../terraform output -raw s3_bucket_name)/ --delete
aws cloudfront create-invalidation `
  --distribution-id $(terraform -chdir=../terraform output -raw cloudfront_distribution_id) `
  --paths "/*"
```

`build.py` cross-compiles: it fetches **Linux** wheels for the **Lambda** Python version
regardless of the machine building the zip, which is what prevents the classic
`No module named 'pydantic_core._pydantic_core'` failure on deploy.

### Automated deploy (GitHub Actions)

`.github/workflows/deploy-group4-notice-board.yml` at the **repository root** runs on
every push to `master` that touches this project. It tests, packages and updates the
Lambda, builds the frontend with the API URL baked in, syncs to S3, then invalidates the
CloudFront cache and waits for the purge to finish.

Required repository secrets (**Settings → Secrets and variables → Actions**):

| Secret | Value from |
|--------|-----------|
| `AWS_ACCESS_KEY_ID` | your AWS credentials |
| `AWS_SECRET_ACCESS_KEY` | your AWS credentials |
| `AWS_REGION` | `us-east-1` |
| `S3_BUCKET` | `terraform output s3_bucket_name` |
| `LAMBDA_FUNCTION_NAME` | `terraform output lambda_function_name` |
| `VITE_API_URL` | `terraform output api_url` |
| `CF_DISTRIBUTION_ID` | `terraform output cloudfront_distribution_id` |

### Infrastructure

| Resource | Notes |
|----------|-------|
| S3 bucket | Private. All four public-access blocks are `true`. |
| CloudFront | OAC with SigV4 signing, `redirect-to-https`, `PriceClass_100`. `403` and `404` both map to `/index.html` so SPA refreshes work. |
| Lambda | `python3.13`, 512 MB, 30 s timeout, handler `lambda_function.handler`. |
| API Gateway | HTTP API, `ANY /{proxy+}` and `ANY /` both proxying to the Lambda. |
| IAM | Uses the workshop's shared execution role — the account denies `iam:CreateRole`. |

The Lambda's `CORS_ALLOWED_ORIGINS` is built by Terraform from the CloudFront domain and
the S3 website endpoint, so adding an origin is a `terraform apply` rather than a code
change and redeploy.

### Teardown

```bash
cd terraform
terraform destroy
```

Read once at startup by `app/config.py`. Locally these come from `.env`; on AWS they are

## Troubleshooting

| Symptom | Cause |
|---------|-------|
| S3 website URL returns `403` | Expected under Tier 3. Use the CloudFront URL. |
| Browser shows a CORS error | The origin is not in `CORS_ALLOWED_ORIGINS`. Terraform sets it from the CloudFront and S3 domains — re-apply after the distribution exists. |
| `No module named 'pydantic_core._pydantic_core'` | The zip was built with native Windows wheels. Re-run `python build.py`, which forces Linux wheels. |
| `python build.py` fails with `PermissionError: [WinError 5]` | A read-only `__pycache__` in `backend/_build`. Delete `backend/_build` and re-run. |
| Deploy is green but the site is unchanged | CloudFront is still serving cached `index.html`. The workflow invalidates automatically; manually, use `aws cloudfront create-invalidation`. |
| `401` on every write | Token missing or expired (60 minutes). Sign in again. |
| Login fails for every account | The employee collection is not empty, so the seed skipped. Check `GET /api/health` for which `repository` is live. |
